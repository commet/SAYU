# "API가 없습니다"에서 멈추지 않는 법

---

저는 SAYU라는 예술 플랫폼을 만들고 있습니다. 핵심 기능 중 하나가 전시 탐색인데, 한국 공공데이터 API들을 연동해서 국내 전시 9,318건을 모아놓은 상태였습니다. 잘 돌아가고 있었고, 여기서 해외 전시까지 커버리지를 넓혀보기로 했습니다.

## 벽

자연스럽게 이렇게 시작했습니다. "전 세계 전시 정보를 제공하는 API가 있을까?"

Claude Code와 함께 리서치를 했습니다.

- **Artsy API** — 2025년 7월 종료
- **Google Arts & Culture** — 공개 API 없음
- **Ocula** — Cloudflare 차단 (403)
- **ArtRabbit** — URL 변경, 전부 404
- **Tokyo Art Beat** — 클라이언트 렌더링, 데이터 추출 불가

전부 막혔습니다. Claude Code도 안 되는 소스를 하나씩 "skipped" 처리하며 포기 목록을 만들고 있었습니다. 그래서 이렇게 말했습니다.

> "API가 없는 게 훨씬 많을 거야. 어떻게든 방법을 찾아내. 포기하지 마. 평범한 게 되어버려."

## 전환

이 시점에서 Claude Code가 접근 자체를 바꿔왔습니다. "글로벌 전시 API"를 찾는 대신, **도시를 단위로** 질문을 바꾼 것입니다.

> ~~"전시 API가 뭐가 있지?"~~
> **"파리의 전시 데이터는 어디에 있을까?"**

이 전환이 모든 걸 바꿔놓았습니다. "글로벌 전시 API"는 없지만, **도시 단위로 내려가니 데이터가 넘쳐나고 있었습니다.**

- **파리** → 파리시청 공공데이터 포털 "Que Faire a Paris" — 인증 불필요, **1,211건**
- **베를린** → 독일 정부 오픈소스 API kulturdaten.berlin — **1,002건** (전시)
- **뉴욕** → Whitney Museum 자체 API, Cleveland Museum CC0 API — **476건**
- **글로벌** → e-flux 아트 미디어 HTML 스크래핑 — **15건** (API 없이 추출)

"글로벌 전시 API"를 찾고 있었다면 절대 만나지 못했을 소스들입니다.

## 왜 이게 통했는가

음악은 Spotify가, 영화는 TMDb가, 도서는 Google Books가 중앙에서 모아놓고 있습니다. 하지만 전시 데이터는 파리시청, 독일 정부, 각 미술관이 각자 관리합니다. **문화 데이터는 본질적으로 로컬 분산형**이고, 이걸 중앙화하려던 서비스들(Artsy, ArtRabbit)은 하나씩 사라졌습니다.

```
중앙 집중형 데이터: 하나의 글로벌 API를 찾으면 끝
로컬 분산형 데이터: 도시별 소스를 찾아서 조합해야 함
```

"글로벌 API가 없다"는 사실은 포기의 근거가 아니라, **내가 다루는 데이터의 구조가 중앙 집중형이 아니라는 신호**였습니다. 데이터의 구조를 이해하면 전략이 따라옵니다.

## 의외의 보너스: 국내 데이터도 좋아졌습니다

해외 확장을 위해 "도시 기반 접근"을 도입했더니, 기존 국내 데이터까지 개선되었습니다.

기존 9,318건 중 58%는 도시 정보가 비어 있었습니다. 한국 API가 "서울특별시 종로구 삼청로 30" 같은 주소를 줬지만, 이걸 "Seoul"로 정규화하는 과정이 없었기 때문입니다. 도시 기반 구조를 만들면서 80개 이상의 패턴으로 **3,304건의 도시 정보를 복원**했고, 도시 정보 누락률이 58%에서 18%로 줄었습니다.

새로운 프레임은 새로운 문제만 푸는 게 아니라, 기존에 보이지 않던 문제까지 드러내고 해결합니다.

## 결과

| | Before | After |
|---|---|---|
| **전시 수** | 9,318 | **12,022** (+29%) |
| **국제 전시** | ~3% | **~25%** |
| **도시 정보 누락** | 58% | **18%** |
| **커버 도시** | 서울 + 일부 | **50+ 도시, 6개국** |

## 가져갈 수 있는 것

**"없다"는 질문이 틀렸다는 신호입니다.** 무언가를 찾을 수 없을 때, 찾는 대상이 아니라 찾는 방식을 의심해야 합니다. "전시 API가 있는가?"라는 질문을 "이 도시의 전시 데이터는 어디에 있는가?"로 바꾸는 순간, 막혀 있던 길이 열렸습니다.

**프레임이 탐색의 방향을 결정합니다.** 같은 목표라도 공급자 프레임("어떤 API가 있지?")과 수요자 프레임("어떤 도시가 필요하지?")은 완전히 다른 탐색 경로를 만듭니다.

**데이터의 구조를 이해하면 전략이 따라옵니다.** 내가 다루는 데이터가 중앙 집중형인지 로컬 분산형인지 — 이걸 파악하는 순간, "왜 글로벌 API가 없는지"가 이해되고 올바른 접근이 보입니다.
